# 从目标到可使用功能

## 接手项目

读入口页面、路由表、依赖清单、构建脚本、服务端配置和最近相关提交。区分静态模板与生成页面、内容仓库与代码仓库、前端与 Worker。记录当前线上版本和本地版本是否一致。项目盘点只给文件名和脚本候选，仍需打开具体文件。

从用户原话整理四项：目标用户、入口、关键动作、可观察结果。例如“产品目录增加交互式线路图”意味着目录卡片、可直接访问的地址、资源路径、返回入口和可用地图，不只是拷贝文件。

## 页面与账户设置

优先延用项目已有的主题变量、字体和组件。用户提供设计变量或初始化方案时，先核对它与现有技术栈是否匹配；静态站可沿用设计变量实现相近外观，不因单个组件或脚手架而迁移全站。初始化命令不是完整设计稿，不推断其包含用户自定义设计。

账户设置依据现有 API 逐项接线：昵称、emoji/上传头像、密码、TOTP、通行密钥、退出和注销。不存在后端能力就先说明并实现必要服务端检查，不能摆一个假的“已开启”标签。注销采用二次确认并说明数据后果；密码、恢复码与认证挑战不进入普通日志。

弹窗需检查短屏、200% 缩放、手机、键盘操作：有最大可视高度，滚动容器有实际高度约束，flex 子项必要时 min-height:0，内容 overflow-y:auto；验证滚轮能到达底部，背景锁滚不误锁弹窗。状态标签的字号、字重、对比度与全局按钮规则分别检查。

## 独立项目接入

检查源码真实资源路径，保留许可证。新增独立子目录，避免全局 CSS/JS 污染。直接 URL 和刷新能加载，图片、字体、动态 fetch、模块路径均可解析。第三方地图等资源检查跨域和离线失败提示。目录入口与构建模板同时更新，不只编辑生成文件。

## 实施与验收

先核对项目规则，最小改动实现目标。按需要使用截图、现有单元检查、构建与关键旅程验证；文案小改不强加测试框架。权限、支付、同步或文件写入须验证服务端行为。用户新增要求写入任务记录，取消一项不自动取消其余待办。
