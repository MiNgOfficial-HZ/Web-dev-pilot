# 外部服务接入流程

先确认服务用途和部署栈，再读所选产品当前官方文档。不要照搬历史收费、产品名称、沙箱域名或签约状态。技能示例中的命令不是服务已安装的证据。

## 通用闭环

列出所需产品、权限、回调和环境变量名。执行环境已授权的安装/代码工作可直接推进；需要用户登录、实名、开通付费产品、签约、DNS 迁移或真实交易时，用当前授权范围及宿主规则决定是否交接。完成后回读后台状态并测试实际链路，记录沙箱/生产环境。

## 支付

用户明确要求接入某个支付平台时，先查找该平台当前的官方接入技能与文档；没有则走官方渠道，先读接入说明。不要把一次性安装参数当作通用配置，也不要把本技能冒充服务商官方技能。

核对“仅使用服务”与“完整代码接入”的区别；已开通产品不等于商户参数就绪。密钥仅放服务端 secret；区分应用签名私钥与平台验签公钥。测试环境密钥也不进入代码仓库和输出。若密钥曾公开，应立即轮换并检查使用记录。

完成：服务端创建订单 → 展示真实二维码/跳转 → 在测试环境完成支付 → 异步通知验签 → 校验应用/商户/金额/订单 → 幂等更新 → 服务端主动查单核对。浏览器 return_url 或截图不能作为支付成功依据。签约、资质、真实付款由用户完成。切换生产环境需核对全部正式参数和发布授权，不仅改网关。

## 域名邮箱

转发地址与发信邮箱分开核对。邮件转发服务的常见步骤为验证目标邮箱、配置邮件 DNS 记录、创建自定义地址路由、发送测试邮件并确认投递。先读现有 MX/SPF，避免覆盖已运行邮件服务。Catch-all 只在用户希望接收未配置地址邮件时启用。转发成功不代表可用域名地址发信；SMTP 发信服务按当前文档另行接入。

## 预约与字体/素材

预约通常只需服务商提供的公开链接；先提供清晰按钮，嵌入则验证 iframe 限制、手机与时区。避免复制带登录 token 的地址。确认邮件签名不默认推断会影响所有预约自动邮件。

字体和资源记录原始来源、权利人、许可版本、用途和是否修改。未知项标“待确认”并询问，不能编造邮箱或作者。内容许可遵循作者明确选择的条款，区分署名、商用、修改和再分发权限。代码原创和第三方库许可分列。云服务说明供应商与服务条款，使用者不因此拥有服务商的版权。
